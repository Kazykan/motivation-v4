# Контекст и архитектурные правила проекта (AI Guidelines)

## 1. Общие принципы
- Проект разделен на две изолированные роли: **Parent (Родитель)** и **Child (Ребенок)**.
- Строго запрещено смешивать бизнес-логику, компоненты и API-вызовы разных ролей в общих файлах. Каждая роль имеет собственную структуру в `src/app/parent/` и `src/app/child/`.
- Все переменные окружения должны браться исключительно из `.env` файлов (например, `process.env.NEXT_PUBLIC_API_URL`). Хардкод URL и ключей строго запрещен.

## 2. Архитектура и State Management (Zustand)
- Для отложенной отправки данных и индикации используется Zustand.
- Хранилище должно содержать:
  1. Буфер изменений.
  2. Флаг синхронизации (`isSyncing: boolean`).
  3. Идентификатор таймера для дебаунса.
- **Optimistic Updates:** Состояние интерфейса обновляется мгновенно. Предыдущий таймер сбрасывается, запускается новый таймер на 1 секунду (дебаунс), после чего буфер отправляется на бэкенд через Axios, а флаг `isSyncing` переводится в `true`.

## 3. API и Сервисы
- Запросы к бэкенду разделены на `parentApi.ts` и `childApi.ts`.
- Используется единый экземпляр Axios (`src/lib/axios.ts`), сконфигурированный через переменные окружения.

## 4. Стиль кода и требования
- Никаких лишних комментариев, эмодзи, «воды» или софт-тока при генерации кода. Только строгая техническая реализация.
- Использовать TypeScript, Tailwind CSS и компоненты интерфейса согласно дизайн-системе. Приоритет отдается компонентам shadcn/ui. Кастомные компоненты создаются только при отсутствии подходящих аналогов в shadcn/ui.
- Дробить интерфейсные элементы на модульные переиспользуемые компоненты для исключения дублирования кода и поддержания единого стиля дизайна. Проверять на дублирование компонентов предлагать бути решения.
- Все функции должны быть отдельно если они будут переиспользоваться не в файлах page.tsx
- Все пропсы должны быть в отдельном файле
